# Glossary

Plain explanations of words used in this folder.

| Word | Meaning |
|---|---|
| **Brief** | Your one page description of what you want to find out, written before any data is opened |
| **Hypothesis** | What you expect to find, written so that it could turn out wrong |
| **Decision rule** | Written in advance: which numbers mean "yes", "no" or "can't tell" |
| **Primary endpoint** | The one number the answer rests on |
| **Secondary endpoint** | Other numbers worth reporting; they never decide the answer on their own |
| **Confirmatory** | Tests a hypothesis on data nobody had looked at yet |
| **Retrospective** | Tests a hypothesis on data you have already seen. Allowed, but said out loud |
| **Exploratory** | Looks for patterns without a hypothesis. Suggests ideas, decides nothing |
| **Preregistration** | Saving the brief and plan (a git commit) before opening the data, so anyone can see they were not changed to fit the result |
| **HARKing** | "Hypothesizing after the results are known": deciding what you expected after seeing the answer |
| **Denominator** | The "out of how many" in a number: the 35 in 27 of 35 days |
| **Reference interval** | The range where 95 % of healthy people fall. Being outside it is not the same as being ill |
| **Decision limit** | A threshold a guideline ties to a decision or a risk, like 135/85 for home blood pressure in Europe |
| **Escalation trigger** | A rule, written in advance, for when a result goes to a clinician |
| **Flag** | A value outside its reference, tracked until someone decides what it means |
| **Semantics** | What the data mean: what each field measures, in which unit, how it was produced |
| **Source** | Where data come from: an app, a device, a lab |
| **Delivery** | One way a source hands over data: an export file, an API |
| **Object** | One kind of record from a source; its **grain** says what one row is (one reading, one night) |
| **Ontology** | The list of things measured (concepts), independent of which app measured them |
| **Metric** | A formula that turns fields into a number, with a version |
| **Front matter** | The few lines between `---` marks at the top of some files, holding status and dates |
| **Positive control** | Proving a search works by finding something you know is there, before trusting "nothing found" |
| **Reproduction** | Same data, same script, same answer |
| **Replication** | New data, does the answer still hold? |
| **Git, commit** | Version history. A commit is a saved snapshot with a message saying what changed |
